## 2. Justifikasi keputusan REPLACE dan REMOVE

### 2.1 REPLACE: pg-boss → BullMQ

Prinsip migrasi melarang mengganti teknologi hanya karena berbeda dari preferensi. Karena itu alasannya dijabarkan di sini.

**Argumen untuk mengganti:**

1. BullMQ tercantum di **Target Core Stack** (wajib), bukan sekadar preferred.
2. **Waktunya paling murah sekarang.** Baru ada dua consumer aktif (`webhooks.process` dan `messages.outbound`), dan antarmuka `PgBossService` sempit. Fitur berikutnya di backlog (Broadcast, Blast, Campaign) akan menambah queue bervolume tinggi; memindahkannya setelah itu jauh lebih mahal.
3. BullMQ menyediakan rate limiter per queue, prioritas, job scheduler, dan ekosistem monitoring (Bull Board, MIT). Ini relevan untuk pengiriman massal yang harus mematuhi batas provider seperti WhatsApp.
4. Redis tetap dibutuhkan untuk state bersama (idempotency, rate limit), jadi BullMQ tidak menambah jenis infrastruktur baru di luar Redis itu.
5. Beban polling queue dipindahkan dari Postgres, yang juga melayani transaksi domain.

**Argumen untuk mempertahankan pg-boss** (alternatif yang sah):

1. pg-boss sudah berfungsi dan teruji. Tidak ada masalah performa yang terukur.
2. Satu dependensi infrastruktur lebih sedikit (Redis tidak wajib).
3. ADR AD-002 dan AD-006 dirancang di atas pg-boss.

**Batasan yang harus dipahami:**

- **Transactional outbox di Postgres tetap dipertahankan.** BullMQ hanya menggantikan transport job. Redis berada di luar transaksi database, jadi outbox tetap menjadi jaminan atomisitas (AD-006). Dispatcher hanya menandai outbox `COMPLETED` setelah BullMQ menerima job, sama seperti perilaku sekarang.
- Dedup `singletonKey` diganti dengan `jobId` deterministik (`outbox-<eventId>`). Handler tetap idempoten (cek status `PENDING` / `PROCESSED`), karena BullMQ juga bersifat at-least-once.
- Redis wajib dikonfigurasi persisten: AOF dan `maxmemory-policy noeviction`. Tanpa itu job dapat hilang.
- **Lisensi:** BullMQ open source berlisensi MIT. Rate limit **per grup** (mis. per channel) hanya ada di BullMQ Pro (komersial). Rencana ini **tidak** memakai fitur Pro; rate limit per channel, bila dibutuhkan, diimplementasikan sendiri.
- Perubahan perilaku yang disengaja: retry dari jeda tetap (pg-boss `retryDelay`) menjadi exponential backoff dengan jitter, sesuai kebijakan yang sudah ada di `contracts/jobs/retry.ts`. Jumlah percobaan tetap sama. Ini hanya mengubah _waktu_ retry, bukan hasil bisnisnya.

**Rekomendasi: REPLACE**, dengan cutover bertahap (expand–contract, lihat WU-05). Keputusan ini membutuhkan persetujuan owner. Bila owner memilih mempertahankan pg-boss, WU-05 dihapus, deviasi dari target dicatat, dan Redis tetap ditambahkan untuk WU-04.

### 2.2 REPLACE (MIGRATE): Next.js → React + Vite

1. **Bukti teknis bahwa Next.js tidak memberi nilai server:** semua route hasil build berstatus statis (`○`), kecuali `/ai-agent/[agentId]` yang dirender dinamis (`ƒ`) hanya karena segmen dinamis tanpa `generateStaticParams`; halaman itu `'use client'` dan tidak memakai data server (koreksi 2026-10-17, lihat 01 §6.3; bukan hambatan Vite); tidak ada Server Actions, route handler, atau SSR data fetching. Middleware hanya mengecek keberadaan cookie, dan cookie itu bisa ditiru tanpa token valid, sehingga proteksinya kosmetik.
2. **Keamanan:** 5 dari 9 advisory produksi berasal dari `next` dan dependensi transitifnya. Migrasi menghapus seluruh permukaan server Next (image optimizer, cache ISR).
3. **Operasional:** container `web` (Node.js) dapat dihapus. Caddy langsung menyajikan file statis.
4. **Kode yang dipakai ulang:** komponen, hooks, `lib/*` (TanStack Query, Zustand, realtime, API client), Tailwind, dan token desain tetap. Yang berubah adalah titik masuk, router, pembungkus navigasi, env, dan Dockerfile.
5. **Tidak ada redesign UI.** Tampilan dijaga dengan perbandingan screenshot Playwright per route.

## 6. Addendum keputusan arsitektur dan kendali risiko implementasi

### 6.1 Koreksi teknis kontrak BullMQ

Rencana awal menulis `jobId = outbox:<eventId>`. Untuk **custom job ID BullMQ**, karakter titik dua (`:`) tidak diperbolehkan karena digunakan sebagai separator internal. **Kontrak target direvisi menjadi `jobId = outbox-<eventId>`**, dengan format berbasis outbox event ID yang deterministik dan bukan hanya angka. `singletonKey` pg-boss lama dalam catatan audit tetap historis dan **tidak** perlu ditulis ulang.

**Dua lapis deduplikasi tetap wajib:** (1) jobId menekan duplicate enqueue selama job masih disimpan di queue; (2) constraints, state transitions dan handler idempoten di PostgreSQL menjaga business-level idempotency saat job didaur ulang, retensi membersihkan completed/failed, worker crash, atau retry. Custom `jobId` **tidak** menghasilkan exactly-once delivery ke provider eksternal. Perlu kebijakan eksplisit untuk kasus timeout setelah provider menerima send tetapi sebelum receipt/outbound state dipersist.

Sumber teknis terverifikasi: [BullMQ Job IDs](https://docs.bullmq.io/guide/jobs/job-ids), [Auto-removal of jobs](https://docs.bullmq.io/guide/queues/auto-removal-of-jobs), [Going to production](https://docs.bullmq.io/guide/going-to-production).
