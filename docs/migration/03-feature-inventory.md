Fitur yang paling berisiko terdampak migrasi:

1. **Jalur inbound dan outbound pesan** (outbox → queue → worker), saat pg-boss diganti BullMQ.
2. **Inbox UI dan Channels UI**, saat Next.js diganti Vite. Keduanya belum punya test E2E, sehingga characterization test harus dibuat lebih dulu (WU-03).
3. **Login Supabase**, saat cookie dan middleware Next dihapus dan saat validasi issuer ditambahkan.

Fitur CRM yang berstatus NOT IMPLEMENTED **bukan bagian dari migrasi**. Fitur-fitur itu adalah backlog produk yang dibangun di atas stack target setelah fondasinya siap (lihat [06 §5](06-migration-roadmap.md#5-di-luar-scope-migrasi)).

### 5.1 Pemisahan test dan kondisi produksi

**CI standar:** Vitest + PostgreSQL sandbox, Redis nyata untuk WU-04/05, Playwright + stub provider Graph API untuk golden path. Jangan memakai token provider live, database produksi, atau data pelanggan. Flaky test harus memiliki trace dan issue yang jelas, bukan di-skip tanpa persetujuan.

**Uji manual terbatas:** alur login Supabase asli dan hasil cutover staging harus dilakukan hanya setelah owner menyediakan environment dan credential dengan scope yang tepat. Sampai itu tersedia, laporkan `NOT VERIFIED` dan blokir enforce/cutover terkait.

### 5.2 Fitur yang tetap bukan bagian migrasi

Contacts CRUD, ticket, lead/deal/pipeline, campaign/broadcast/blast, dashboard/report, rules automation, backend AI Agent, dan notifikasi tetap backlog produk sebagaimana §3. Jangan memasukkan mock UI yang ada sebagai delivery fitur CRM; migrasi ini menjaga agar UI lama tidak memburuk, bukan membangun backend CRM baru.
