## 1. Prinsip eksekusi

1. **Satu work unit = satu PR ke `main`.** Owner yang melakukan merge. WU-05 dan WU-06 dipecah menjadi beberapa PR bertahap.
2. **Satu subsistem per WU.** Tidak pernah mengganti queue dan frontend dalam PR yang sama.
3. **Verifikasi vertikal setiap WU.** API, logika bisnis, dan database sudah memakai stack target, jadi "vertical slice" diwujudkan sebagai **skenario golden path** end-to-end yang dijalankan ulang setelah setiap WU:
   1. Login (dev-session) → Inbox terbuka.
   2. Webhook WhatsApp bertanda tangan (dikirim ke API lokal) → journal → outbox → queue → worker → contact/conversation/message → muncul di Inbox lewat realtime.
   3. Webhook yang sama dikirim ulang → tidak ada duplikasi.
   4. Agent membalas dari UI → outbox → queue → adapter → **mock Graph API** (`META_GRAPH_API_BASE_URL` ke server stub lokal) → status `SENT` → receipt `DELIVERED`, lalu `READ` (tidak mundur).
   5. Assign ke diri sendiri, resolve, reopen → timeline sistem dan audit log tercatat.
   6. Provider mengembalikan error transient lalu sukses → retry → `SENT`. Error permanen → `FAILED` dan tombol retry berfungsi.
4. **Test yang gagal tidak dihapus atau dilemahkan.** Mock tidak menggantikan test integrasi tanpa dicatat.
5. **Operasi destruktif** (drop schema `pgboss`, mengubah aturan FK, menghapus data) selalu meminta persetujuan terpisah, meskipun roadmap sudah disetujui.
6. Setiap WU memperbarui `08-migration-execution-log.md` dan `09-regression-test-results.md` (dibuat saat WU pertama dieksekusi).

## 8. Definition of Ready, Definition of Done dan protocol manusia–AI Agent

### 8.1 Definition of Ready

1. Semua keputusan owner yang ditetapkan sebagai gerbang pada WU terkait memiliki nilai, approver dan tanggal persetujuan. Untuk WU-00, `DEC-01..09` semuanya ditutup eksplisit; _defer_ dianggap keputusan, bukan persetujuan menjalankan WU opsional.
2. Dependency WU berstatus DONE dari PR sebelumnya dan dependency tiket internal selesai. Periksa source `main` dan rebase/merge policy tanpa menimpa hasil kerja lain.
3. Database target sudah dipastikan melalui env guard. Boleh menggunakan `vynor_test` / `vynor_e2e` / `vynor_shadow` sesuai peruntukan; **jangan** memakai DB live dengan kredensial test.
4. Untuk WU-04/05/06/07/08/10 golden path WU-03 sudah tersedia, kecuali ada alasan khusus yang disetujui owner.
5. WU risiko tinggi mempunyai rencana rollback dan batas cutover yang bisa diverifikasi.

### 8.2 Definition of Done

1. PR scoped pada satu WU, dengan diff dan file list yang bisa diaudit.
2. Format/lint/typecheck/build/test yang berlaku PASS; setelah WU-03 golden path E2E dan Channels E2E PASS pada environment yang relevan. Jangan mengganti perintah sukses dengan klaim tanpa output.
3. Verifikasi bisnis **vertical slice** mencakup komponen terhubung, bukan hanya compile modul baru. Catat screenshot baseline/hasil visual bila menyentuh frontend.
4. `08-migration-execution-log.md` dan `09-regression-test-results.md` diperbarui sesudah tahap eksekusi dimulai; rekam SHA dan perintah persis, failure dan NOT VERIFIED.
5. Rollback dan caveat operasi terdokumentasi; tugas bernilai DONE **hanya setelah owner merge dan sign-off gate deployment apabila berlaku**.

### 8.3 Batas otomatisasi

AI Agent boleh membaca kode, melakukan analisis statis, menyusun diff, menjalankan test DB sandbox yang sudah diverifikasi, dan membuat PR pada branch yang diberi izin. AI Agent **tidak** boleh menganggap persetujuan implisit, merge otomatis, force-push, drop schema, reset/clean destructive, mengakses provider nyata, menyentuh DB non-test, mengubah aturan FK, atau enforce auth issuer production tanpa gate terpisah.

**Satu tiket per prompt.** WU memiliki beberapa tiket yang boleh dikerjakan berurutan di branch PR yang sama; agent harus berhenti dan menunjukkan hasil tiap tiket agar owner dapat mereview jika risiko tinggi. Jangan menggabungkan perubahan WU-05 dengan WU-06 dalam satu PR.

## 9. Protokol handoff dan urutan awal yang aman

1. **Owner membaca `agent/01-DECISION-REGISTER.md`** dan mengisi nilai `DEC-01..09`. Alternatif `DEFER` untuk DEC-07 valid; semua gate destruktif tetap `PENDING`.
2. **Kirim satu paket ZIP kepada AI Agent** atau masukkan file ke working repo setelah diff direview. Entry point agent `agent/00-START-HERE.md`; dokumen 01–07 adalah sumber rencana; `agent/VYNOR_AGENT_TASKS.json` adalah struktur pekerjaan; `agent/tickets/` memberikan tugas individual.
3. **Pertama kali hanya `MODE: REVIEW_ONLY`, `TICKET_ID: VYN-00-01`**. Agent wajib mengonfirmasi repo TS, status Git/untracked docs, `origin/main`, worktrees lain, dan menyajikan checklist keputusan yang belum jelas tanpa perubahan kode/DB.
4. **Sesudah owner secara tertulis memberi izin WU-00**, buat branch dokumen dari basis terverifikasi; salin perubahan dokumen dengan hati-hati, commit dokumentasi pada branch; buat PR ke `main`. WU-00 **tidak melakukan migrasi aplikasi**.
5. Lakukan WU-01 (health), WU-02 (security), WU-03 (golden path). Hanya setelah bukti WU-03 lulus, kerjakan WU-04 → 05a → 05b dan 06a–d. WU-07/08 independen setelah WU-03, 10 setelah 05b.
6. WU-09 dan 05c tetap ditahan bila belum ada persetujuan eksplisit. WU-11 menutup laporan, bukan menyelesaikan fitur CRM yang belum dibangun.

## 10. Release gate dan perubahan yang harus dilarang

- **WU-05a:** `jobId` target `outbox-<eventId>` (bukan `outbox:<...>`). Tes fault injection wajib; `removeOnComplete` tidak boleh dijadikan satu-satunya proteksi idempotency. AOF tidak menjamin zero-loss; butuh rekonsiliasi.
- **WU-05b:** verifikasi pg-boss drain per environment dan `GATE-CUTOVER` disetujui; rollback harus menghindari duplicate send ke provider.
- **WU-05c:** `DROP SCHEMA` hanya `GATE-DB-DROP` + otorisasi environment, backup, dan restore test; jangan memakai `CASCADE` sebagai shortcut tanpa impact review.
- **WU-06d dan WU-08 enforce:** `GATE-AUTH-LIVE` wajib untuk cutover production; bila Supabase live belum teruji, klaim produksi = `BLOCKED/NOT VERIFIED`.
- **WU-09:** jangan tulis inbound attachment sebagai `CLEAN` tanpa scan bila kebijakan keamanan belum disetujui; default `DEFER`.
- **Sepanjang migrasi:** public schema PG tidak berubah pada WU wajib; fitur CRM baru, UI redesign, Fastify, upgrade Prisma, Keycloak, dan Socket.IO Redis adapter berada di luar scope.
