- Perilaku yang diimplementasikan:
  - Claim: satu skrip Lua (GET, lalu SET PX 60 s bila kosong), jadi tepat satu request memegang key. Lease = nilai `IN_FLIGHT` persis yang ditulis claim itu; complete dan release adalah compare-and-set/compare-and-delete atas lease, sehingga request yang melewati lock 60 s tidak menimpa claim baru.
  - `COMPLETED` disimpan 24 jam berisi status dan body untuk replay (`x-idempotent-replay: true`).
  - Fingerprint: SHA-256 atas query dan body dengan key objek diurutkan. Key yang sama dengan payload lain → `422 IDEMPOTENCY_KEY_REUSED`, baik saat request pertama masih berjalan maupun sudah selesai. Payload yang sama dengan urutan key berbeda tetap replay.
  - Key Redis: `vynor:idem:<workspaceId>:<sha256(method path key)>`. Client key dan path URL tidak tersimpan apa adanya; log hanya memuat pesan error Redis.
  - Redis tidak terjangkau → `503 SERVICE_UNAVAILABLE` sebelum handler berjalan. Request tanpa `Idempotency-Key` tidak menyentuh Redis.
