# 03 — Codebase Quality Audit (Phase 4)

Severity legend: **Critical** (security, data integrity, runtime or deployment failure), **High**
(substantially raises regression risk or complexity), **Medium** (maintainability/structure),
**Low** (cosmetic/optional). Each finding has an ID used in the risk register and roadmap.
"Latent" means the defective path exists in code but is not reachable by any current caller.

## Overall assessment

The repository is young (Phase 0 foundation + UI prototype) and in reasonably good health: strict
TypeScript, green lint/typecheck/build, a documented ADR set, Zod contracts, migration drift checks,
and CI quality gates. The main problems are **not** tangled code but:

1. a handful of wiring defects between layers (health probe paths, config propagation, outbox
   "skipped" semantics, correlation-ID handling);
2. contract drift between parallel sources of truth (error codes, enums, docs vs code, duplicated
   infra files);
3. cross-cutting logic copied into many places (correlation IDs, loggers, error payloads);
4. a frontend that is a UI prototype with mock data embedded in page files and a client-side
   fabricated authorization context;
5. thin automated coverage exactly where refactoring is riskiest (filters, interceptors, guards
   with DB, worker dispatcher, realtime), with brittle source-string "verify" scripts as the main
   frontend safety net.

## 10. Naming

Naming is largely consistent (kebab-case files in backend/packages, PascalCase React components,
`resource:action` permissions, `vynor.<domain>.<action>` queues). Inconsistencies worth noting but
**not** worth cosmetic renames: storage service `rustfs` vs MinIO image; `RustFsStorageAdapter`
for a generic S3 adapter; web route `/campaigns` labelled "Broadcast"; `ai-agent` (route) vs
`ai-agents` (lib folder). Renaming these would touch public paths or verify-script literals for
little value — **keep**.
